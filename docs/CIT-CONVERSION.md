# CIT 转换规则

转换根据包内条件和目标版本能力决定，不读取包名作特殊判断。材质包可以使用任意合法命名空间、文件名和相对资源路径。

## 版本能力

| 目标 | 可直接输出的条件外观 |
| --- | --- |
| 1.7.10–1.13.2 | 保留和迁移 OptiFine / MCPatcher CIT；不把不支持的模型功能当作已实现 |
| 1.14–1.21.3 | 兼容的数字 CustomModelData 写入旧模型覆盖；其他 CIT 条件由客户端支持 |
| 1.21.4 | 数字 CustomModelData 使用原版数值分派 |
| 1.21.5–26.4 | 在数字 CMD 外，可将指定附魔及等级、损伤、数量、药水和部分烟花条件编译为原版组件谓词或数值分派 |

1.21、1.21.1 和 1.21.4 不能直接使用 1.21.5 的 `minecraft:component` 条件 API。原版无法表达所有 OptiFine CIT 条件，不能通过修改 `pack_format` 补出客户端缺少的能力。

新版原版模型降级至 1.13–1.21.3 时，可将可表达的附魔、药水、损伤和纹饰条件编译为 CIT。叠加的平面图层合并为旧物品模型，拉弓等运行状态写入模型覆盖。背包显示条件在旧版没有独立的逐图层过滤接口，降级后的标记也可能显示在手持场景；报告会说明。更早版本保留完整原始定义供再次升级，不声称其旧模型接口能完整表达这些功能。

## 条件与优先级

- 同一个物品按 CIT 权重从高到低匹配，同权重按稳定的原始资源路径排序；保留未命中时的作者模型树。
- 附魔 ID 列表表示或关系，等级条件应用于命中的附魔。等级区间可以不连续，边界不会扩展到相邻等级。
- 只有 `enchantmentLevels`、没有附魔 ID 的规则，在 OptiFine 中表示全部附魔的等级总和。原版模型无法直接求和，保留并说明；不将其当作任意单个附魔满足等级。
- 损伤的整数值和百分比使用不同的数值域；位掩码、不能精确表达的小数或未知条件不作近似替换。
- 多个条件是且关系。不能合并的联合条件不得覆盖或丢弃其中一项。
- 更高优先级规则无法解析时，不用较低优先级规则冒充其效果。缺资源的已知条件回退到原始基础外观，原规则继续保留。

烟花支持飞行时长，以及标准爆炸列表非空条件。任意 NBT 正则、名字、穿戴盔甲、存储附魔与普通附魔的语义差异等，必须保留真实限制。不能由现有谓词准确表达的规则继续需要兼容的 CIT 客户端。

## 模型与资源

保留模型几何、父链、显示姿态、动画元数据及命名空间。弓、弩、鱼竿、盾牌和三叉戟按目标原版状态模板替换对应外观，不将所有状态指向同一张图。

生成前检查资源路径、父模型与贴图槽循环、贴图是否存在、同名资源冲突。不存在的资源不接成紫黑分支；目标尚未引入的物品、纹饰或染色来源在报告中列出，其他有效状态继续转换。原版药水的染色层与完整着色图分开处理。

模型树深度、分支数、图层数及输出体积均设上限，避免异常包导致失控展开。超过上限时保留原始规则并说明原因，不删条件以换取输出成功。

## 往返与用户改动

`fastpack/native-cit.json` 保存原始原版物品定义、模型及生成文件摘要；`fastpack/cit-items.json` 保存 CIT 接入前后的原模型。它们随输出包保存，不能在需要往返恢复时删除。

未被修改的生成资源再次升级时恢复完整定义，包括原有场景过滤、叠加和状态分支。编辑或删除了生成规则、模型时，保留用户改动并报告。恢复只在当次转换执行，后续转换不会持续覆盖作者编辑。协议载体的自动映射由原适配器处理，CIT 转换只接入其作者基础定义，避免重复套映射。

## 增加规则时的要求

先判断目标版本是否有等价能力，再添加解析和输出。新条件默认不支持，不能因为不认识就忽略。升级与降级应共用明确的语义，必要时保留原始数据；不增加按包名或用户文件夹判断的例外。

至少验证区间边界、未命中回退、规则优先级、组合条件、运行状态、缺失资源、重复转换、作者编辑和往返恢复。已有全版本矩阵覆盖全部 80 个目标标签的 6400 种 CIT 资源迁移组合；这不代表每个客户端都能渲染所有条件。客户端能力限制必须继续出现在文档和转换报告中。

相关实现位于 `cit_rules.rs`、`cit_conditions.rs`、`cit_native_rules.rs`、`native_cit*.rs`；回归用例位于对应的 `*_tests.rs`。
